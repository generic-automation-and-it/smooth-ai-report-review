# Eval Harness — chunk-review model

Regression-tests the `ai-review-report` chunk-review LLM against a labeled corpus (DR golden set + seeded defects) so prompt / model / LADR changes don't re-introduce known false positives or weaken detection. Context/decision narrative: **LADR-033** in `../../SKILL.md`.

## TL;DR

Two-axis harness: **precision** (must-NOT-flag DR-001…014 — zero-tolerance at Crit/High/**Med** on the fixture's OWN `forbidden_claim`; unrelated true findings are reported, not blocking) and **recall** (must-catch seeded defects at ≥ labeled severity, threshold-gated). Drives the real `review-in-chunks.sh` over the CI transport and makes paid calls — opt-in only (local entrypoint, `workflow_dispatch`, or the scope-checked `pull_request` required check), never the default bash-test path.

## Non-Negotiables

- **Repair a `must-not-flag` fixture by REMOVING surface, never adding scaffolding.** Every addition is new material for the reviewer to (correctly) flag — learned twice (DR-015, DR-009), each costing a paid run. Delete offending lines and accept a thinner fixture; the injected DR context carries the explanation, the fixture only carries the *shape*.
- **A `must-not-flag` fixture fails on its OWN claim, not on any finding.** Each manifest's `forbidden_claim` ERE describes the WRONG claim; only a flagged Crit/High/Med matching it fails the fixture, other true findings are counted as `Unrelated findings` and don't block. Severity-only was abandoned because every precision failure across repeated paid runs was a correct finding, never a DR re-raise, and the set never converged. A manifest with no `forbidden_claim` keeps strict behaviour, but no shipped fixture relies on it (DR-014's claim is an objection to LADR-10's chosen database-per-tenant approach). The hazard when adding a claim: a pattern loose enough to match anything makes the fixture **unfailable**, invisible in a green run. Pin every new claim from BOTH sides in `test-evals.sh` Case Q (fires on re-raise phrasings, not on adjacent true findings) and mutation-test it. Unrelated findings are still hygiene debt.
- **A `must-catch` `min_severity` states what the finding must BLOCK at, not how alarming it sounds.** Critical and High both `request-changes`, so demanding CRITICAL where HIGH blocks only fails on tier choice. MC-004 → HIGH (consistent with MC-005); MC-003 → MEDIUM (regresses exception type only), while MC-001 keeps HIGH to preserve that distinction. Cost: MEDIUM doesn't block and `ai-analyse` selects on severity (LADR-042), so an MC-003-class regression is now in the autonomous fixer's remit — fine for restoring a deleted guard, not for a judgement-call fix. Lower a bar only with a reproduced failure signature and a named sibling fixture it is made consistent with; never to turn a red eval green.
- **A `must-not-flag` fixture should contain as little flaggable surface as possible.** `forbidden_claim` stops unrelated findings blocking; it doesn't make them free (tally noise, triage time). Read `after/` as the reviewer would and remove anything you would legitimately raise.
- **The fixture must agree with the context injected beside it** (`corpus/context/code-review-standards*.md`). A fixture contradicting its own DR text punishes the model for noticing a real contradiction.
- **A failed chunk is an INFRA failure, never a clean review.** On chain exhaustion `review-in-chunks.sh` writes a NON-EMPTY stub plus a LADR-031 `chunk_<n>.failed` flag; the stub scores as "no findings", so every must-not-flag fixture passes (an outage once reported precision 100% having reviewed nothing). `run_fixture` checks the flag **before** the emptiness test, and detection is flag-file existence ONLY — never a grep for stub text (LADR-031). Pinned in `test-evals.sh`.
- **`EVAL_PARALLEL` trades wall-clock for rate-limit risk, nothing else.** Bounded pool (default 4, `wait -n` throttle, serial fallback below bash 4.3 — macOS ships 3.2). Fixtures are isolated (own sandbox + `ci_temp/`, artifacts keyed on id); the shared resource is the model endpoint, and a rate-limited call is an INFRA failure → flaky required check. Raise the default only with evidence from a real run.
- **The driver tallies in launch order, never completion order.** Parallel must produce a byte-identical RESULTS table to serial (pinned in `test-evals.sh`). Workers write one `kind|id|verdict|detail` line to a result file and a log the driver replays in order. An INFRA verdict counts as infra ONLY — never in the precision or recall denominator; re-check this whenever the counters are refactored.
- **Do not trim installed provider config to the selected eval provider.** opencode resolves SDK packages only for the provider used (zero saving), and provider-qualified fallback targets (e.g. `go-responses`) may name another configured provider — filtering breaks them at runtime.
- **Workflow ↔ script paths are coupled.** `.github/workflows/llm-eval-harness.yml` invokes `scripts/eval/run-evals.sh` by hardcoded path (as the gate does `../review-in-chunks.sh`). Rename/move → change workflow and scripts in the same commit.
- **`run-evals.sh` and `local-evals.sh` make real, paid calls** and are never safe for the default test path. The default-path-safe test is `test-evals.sh` (stubbed via the `EVAL_SELFTEST` seam).
- **Scoring uses the pipeline's own grammar (LADR-012).** Only `[VERIFIED]` Crit/High/Med count; `[SPECULATIVE]` and "None found" (case/whitespace/bold/period tolerant) never do. Never reimplement severity detection outside `lib/score-review.sh` — extend it there.
- **Precision is intentionally stricter than the gate.** A DR re-raised at **Medium** fails the eval though the gate blocks only on `[VERIFIED]` Crit/High (LADR-012/015). Don't "fix" the bar to match the gate.
- **Env vars are namespaced `OPENCODE_REVIEW_REPORT_*`.** Legacy `OPENCODE_PROVIDER` / `OPENCODE_MODEL_*_REVIEW` / `OPENCODE_<P>_URL` names were retired in LADR-032 (`OPENCODE_CLI_VERSION` is the exception: it is the live opencode version pin again, per the root naming convention); API-key Secrets keep `OPENCODE_<P>_API_KEY`. The eval uses the gate's designed-model Variables + Secrets. `run-evals.sh` defaults `*_SECONDARY` / `*_ORCHESTRATOR` to `*_PRIMARY` so a non-GEMINI chain stays same-family for `lib/resolve-provider.sh`; never reintroduce hardcoded Gemini literals.

## System Context

Per fixture, `run-evals.sh` builds a `mktemp` git sandbox (`before/` or empty base, then `after/` as head), assembles the DR standards corpus at the production path `.agents/skills/code-review-standards/SKILL.md` so `MANDATORY_CONTEXT_FILES` injects the same context production does, and runs the real `../review-in-chunks.sh` with `OPENCODE_MODEL_ID=$OPENCODE_REVIEW_REPORT_MODEL_PRIMARY` — the eval target is the genuine prompt assembly + two-tier chain, not a reimplementation. Concatenated `ci_temp/reviews/chunk_*.md` is scored by `lib/score-review.sh` and gated on the fixture's `kind`. Sandbox and `WORK_ROOT` are wiped on EXIT, so the `EVAL_ARTIFACT_DIR` archive (`<id>.review.md`, infra `<fixture>.lastlog`) is the only record of what the model flagged; CI uploads it with `if: always()` because the eval step exits non-zero on regression.

## Key Behaviors

- **CI triggers.** `pull_request` is a required check (draft/fork skip via job `if:`); relevance is decided by the in-job `Scope check`, not a `paths:` filter, because a path-skipped required check reports nothing and wedges the PR. Only `.agents/skills/ai-review-report/**` or the workflow itself pay for model calls. The post-merge `push`-to-`main` canary is retired (same diff, second bill); a merged fork PR touching the pipeline needs a manual dispatch.
- **Decision-model scoring (LADR-093) is MEASURED, never gated on.** The verdict comes from pre-merge chunk markdown, unchanged. With `EVAL_DECISIONS` on (default: `OPENCODE_REVIEW_REPORT_ENABLE_DECISIONS`), `record_decisions` runs the production post-merge path (`merge-findings.sh` → `score-findings-decisions.sh` in **annotate**) per fixture-sample, and `lib/decisions-report.py` reports, after the verdict, separation (AUC) between known false positives and true catches plus what `filter@t` / `demote@t` / `sev@c` policies *would* have done — applied offline, so the measured document is never altered. Rules: it must never assign `fail` or abort the run (`test-decisions-report.sh` greps for both); a sample whose decisions failed is **excluded** and named, never counted clean; a sample with no findings **is** counted; ground truth is the corpus matched on structured title + rationale (post-confidence-gate, so both baselines are reported, not assumed equal). Act on a policy only when it removes DR re-raises **without** losing a catch across several runs (`EVAL_SAMPLES` > 1).
- **Planted findings calibrate the judge where the reviewer raises nothing.** Every must-not-flag manifest carries `known_false_positive` (phrased to match its own `forbidden_claim`), every must-catch `known_true_positive`, both quoting an `evidence_line`. `calibrate-decisions.sh` scores each alone through the production scorer against the real diff in variants **as-is**, **stripped** (comments removed — fixture "DO NOT flag" comments would hand the judge the answer key) and **stripped+rules** (DR standards passed as the scorer's optional rules file, adding the separate `sanctioned` question). It calls only the decision provider and never changes `fail`. Keep planted text honest: a wrong claim must read as a reviewer would write it, and match `forbidden_claim` (enforced by `test-decisions-report.sh`). Conclusions: `supported` judges evidence, not policy, and is swayed by in-diff comments (`review_rules.untrusted_content` doesn't neutralise them); severity reconciliation is a weak lever; project rules via `sanctioned` separate planted false positives almost perfectly with no catch lost — but those rules were written for these fixtures, so treat it as an upper bound. Single runs are near-deterministic.
- **Real findings overrule planted ones.** `corpus/real-findings/` holds live gate findings with a human verdict and the score the gate computed then (committed because artifacts expire; never re-scored); `calibrate-decisions.sh` reports them at no cost. Real accepted findings scored `supported` mean **0.43**, so filter/demote at 0.5 would hide most real problems (planted catches never went below 0.58) — real findings describe cross-code behaviour one hunk can't prove. **`supported` must not demote or filter anything**; it is display-only, and `sanctioned` is the more promising lever. Label every skipped gate finding `fp` so the precision side gets real data.
- **Labels come from `/ai-review execute` (LADR-096).** Execute writes an invisible `ai-review-decisions` block (`N: fix` / `skip intentional` / `skip invalid` / `skip deferred`) keyed on the review's `<!-- ai-review-report run=<id> -->` marker; `harvest-real-findings.sh --from-pr N` / `--scan [--limit N]` turns it into records with `label_reason`. **`deferred` and anything unrecognised are never harvested** — a mislabelled `fp` makes a suppressing policy look safe. The **latest** decision per finding wins, deferred included: a later deferred removes an earlier record; a correction refreshes it, or removes it if the artifact expired — a superseded label must never survive. Otherwise idempotent; expired artifacts are reported and skipped, so a periodic `--scan` inside the retention window is the whole procedure. `sanctioned` and `previously_skipped` are recorded and reported (`skipped@0.50`), but neither may act until the real set shows zero lost true positives (LADR-096 phase 5).
- **`fix_skip` is measured, and the eval scores what the gate scores (LADR-098).** `calibrate-decisions.sh` and `record_decisions` call the scorer exactly as Step 17.6 does: `fix_skip` asked, code context read at the sandbox head, and (eval) the per-chunk rules from `ci_temp`. Records carry `fix_skip`, `fix_skip_p`, `code_context` and `fix_skip_asked` so an unanswered question stays in every denominator; the report counts answers and answers-with-distribution — the live check that the provider returns `probabilities.fix`. fix_skip ground truth (`fixskip_truth`) counts a human-labelled finding at ANY severity (`ai-analyse` acts on Low), while gate-verdict tables keep the Medium-and-above rule. `fixskip@0.50` is what `OPENCODE_ANALYSE_DECISIONS_MODE=filter` would withhold (Medium/Low, P(skip) ≥ 0.50, hunk found — one helper, `fixskip_withholds()`); section 1d reports a predicted SKIP on a real fix as a prediction error at any severity and, separately, the part that filter would withhold. The harvester keeps the full reviewed `head`, the base branch tip as `base_tip` (not the merge base — a re-score resolves it, LADR-075) and the gate's `fix_skip` prediction (a score, never a label). Code-context scores aren't comparable with older records; use `OPENCODE_REVIEW_REPORT_DECISIONS_CODE_CONTEXT=0` for the hunk-only baseline.
- **The two axes are NOT symmetric — don't collapse them into one knob.** Precision is zero-tolerance (every DR is a confirmed false positive); recall is threshold-gated (`EVAL_RECALL_THRESHOLD`, default 80%, majority of samples) because non-determinism makes a single miss a poor fail signal.
- **A fixture must not itself contain a real defect** (e.g. DR-001's get-only props set in an initializer → CS0200); otherwise a correct flag is miscounted. Hygiene is a correctness requirement. Always include an inline "do NOT flag" steering comment in `after/` naming the DR surface and carving out adjacent legitimate territory — the model reads the comment, not the manifest (see DR-006 / DR-014). A DR fixture protects the LADR's *chosen approach*, not surrounding code; DR-014's `<summary>` shows the "adjacent code is out of scope" wording.
- **`EVAL_SAMPLES=1` is the default; >1 amplifies noise.** It makes precision worst-case and recall majority. To diagnose flakiness use `EVAL_SAMPLES=3` with `EVAL_FILTER=DR-NNN`.
- **`test-evals.sh` must stay green — the selftest seam is the contract.** If you change `lib/score-review.sh`, `run-evals.sh`'s scoring call, or the result-table format, update the canned `<id>/selftest-review.md` fixtures and aggregation cases.
- **Self-test → paid-call path is a one-way trip.** A paid-only branch not exercised by `EVAL_SELFTEST` can no longer be regress-tested; the triage archive is guarded by `EVAL_ARTIFACT_DIR` precisely to keep the default path unchanged (unset for `local-evals.sh` and the self-test). Inspect the archive before deciding a FAIL is a real regression vs fixture hygiene.
- **Don't bake fixture content into `run-evals.sh`.** The corpus is data; new DRs/MCs go under `corpus/`. The runner only walks manifests and sets up sandboxes.

## Quality Constraints

- **All scoring/gating logic must be testable via `EVAL_SELFTEST`.** No real-path branch may be unreachable in the selftest; a new gate type or severity rule needs a canned review and a `test-evals.sh` case.
- **No new model transport.** Reuse `lib/resolve-provider.sh` + `lib/prepare-opencode-config.sh` + `lib/opencode-health.sh` + `lib/opencode-with-fallback.sh`. Never call `opencode` directly or add a parallel chain/env var — the eval must exercise what production uses.
- **No silent transport changes.** `OPENCODE_REVIEW_REPORT_*` is the full surface, exposed at job scope in the eval workflow; adding a provider is a LADR-worthy change, not a one-line `opencode.json` edit.
