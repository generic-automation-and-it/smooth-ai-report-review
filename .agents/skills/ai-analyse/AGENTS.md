# ai-analyse

## TL;DR

Autonomous counterpart to `/ai-review`: consumes the OpenCode Review Report's low/medium findings and applies only safe, scoped edits in CI. Critical and high findings remain human-owned.

## Non-Negotiables

- Touch only 🟡 Medium and 🔵 Low findings from the trusted gate-authored review body.
- **Never edit tests, the test framework, or evals by default ("test in the loop").** The suite is the independent oracle for a fix; a self-fix that also rewrites tests can mask its own regression. Eval harnesses are the same oracle one level up — they are what proves the *reviewer* still works — so `eval/` and `evals/` directories are covered by the same rule: harness, scorer, corpus fixtures and manifests. A manifest carries the must-catch recall label, so a fixer able to edit it can turn a failing eval green by relabelling the expectation, which is the eval-side twin of the failing-test rule below. The workflow reverts any such edit before commit unless the `OPENCODE_ANALYSE_ALLOW_TEST_SELF_FIX` Variable is truthy — **off by default, and it must stay off**: test and eval changes belong to a human, via `/ai-review` or by hand. Enforcement is deterministic in `scripts/lib/filter-test-self-fix.sh`, not left to the model. The eval rule matches the **directory segment**, deliberately: harness, scorer, corpus and manifests share no naming convention, and matching broadly means a consumer's production `src/eval/` is caught too — the safe direction for an edit guard, since the failure mode is only "a Medium/Low fix was not applied" and every reverted path is named in the summary comment.
- **Soft-item routing is deterministic (LADR-101).** With test self-fix off, T testing gaps are pre-decided SKIP before the failing-test filter and never sent to the model; a post-model completeness guard appends visible SKIP rows for every omitted in-scope identifier. Neither these rows nor other autonomous SKIPs write the human-owned Skip Areas channel.
- **Never fix a finding whose basis is a failing test.** A red test is evidence that a human needs to decide which is right — the code change or the test. Resolving that disagreement silently destroys the only evidence it existed. The deterministic filter `scripts/lib/filter-failing-test-findings.sh` withholds such findings before the model sees them (LADR-056); the prompt rule reinforces this regardless of the `OPENCODE_ANALYSE_ALLOW_TEST_SELF_FIX` toggle.
- **The test gate keeps all of its own state outside the repository.** `run-test-gate.sh` stages its report, per-suite capture files, candidate lists, and failure logs in a `mktemp -d` and publishes them to the caller's path from an EXIT trap. It must never write working files under the tree it is testing. The gate runs suites from the repo root, and a suite is entitled to clean up its own scratch dirs there — `test-code-graph.sh` legitimately does `rm -rf ci_temp`. While the gate kept its state in `ci_temp/test_gate/`, that deleted the gate's own files mid-run: the *next* suite in `LC_ALL=C` order could not be launched (its stdout redirect had no parent directory, so bash returned 1 without running it), `tail` on the missing capture file tripped `set -e`, and the gate exited 1 before writing a report. The workflow rendered that as `test-suite-failed` naming a suite that never ran, with no failure output and no `FAILED_SUITE=` list — a phantom regression that blocked a push while every real suite was green. Pinned by `test-run-test-gate.sh` case 12. Publishing must stay in the trap: the gate has five exit paths.
- Never edit for 🔴 Critical or 🟠 High findings, even if their suggested fixes appear nearby, and never list them in the summary table — they are omitted entirely (no FIX, no SKIP row), leaving Critical/High human-owned.
- Headless CI runs edit-only: no `git`, no commit, no push. The workflow owns those side effects.
- Never emit or create a `/ai-review` trigger. The workflow commit carries an `[ai-analyse]` marker for traceability only — the loop is bounded by the incremental-cycle cap (`OPENCODE_ANALYSE_MAX_INCREMENTAL`), not by a head-commit sentinel. A no-edit cycle (all SKIP) ends the loop early because nothing is pushed.

## Key Behaviors

- The workflow inlines `SKILL.md` into the prompt because opencode headless `run` does not auto-activate project skills and the `analyse` agent has the `skill` tool disabled.
- The agent is intentionally edit-only in `.agents/skills/ai-review-report/assets/opencode.json`: read/list/grep/glob/edit allowed; bash, skill, task, webfetch, websearch and execute (v2 Code Mode, whose runtime has its own `fetch` — LADR-094 in the report skill) denied.
- Summary comments are posted by the existing `.agents/skills/ai-review/scripts/copilot-review.sh summary` helper so GitHub plumbing stays centralized.
- The deterministic filter `filter-failing-test-findings.sh` withholds findings whose basis is a failing test before the model sees them, and the withheld findings are reported in the summary comment so the filtering is auditable.
- The no-model shortcut uses the scope extractor's non-empty/non-`None found` predicate, not identifier syntax: orchestrator-written Medium/Low findings can be unnumbered and still need the fixer (LADR-101 correction).
- **Decision-model support is one-directional (LADR-097 in the report skill).** With `OPENCODE_ANALYSE_ENABLE_DECISIONS` truthy, `pipeline-ai-analyse.yml` runs ai-review-report's `lib/recommend-fix-skip.sh --scope analyse` on the already failing-test-filtered Medium/Low sections, then `scripts/lib/apply-decisions-to-scope.sh` either annotates each scored finding (`annotate`) or also withholds the ones the model recommends skipping at `P(skip)` ≥ `OPENCODE_ANALYSE_DECISIONS_MIN_PROBABILITY` (`filter`). It can only annotate or remove — never add a finding or turn a SKIP into a FIX — so it needs no coverage fence: withholding is the conservative direction for an unattended fixer. Unscored findings, and findings whose diff hunk was not found, are never withheld. Withheld findings and the full recommendation table go into the summary comment (count from `<report>.count`, never re-derived). Both libs are `[ -f ]`-guarded in the workflow because the YAML runs from the default branch against the PR's scripts. The recommendations are never labels. **Env vars and who receives them** (skill-secret-handling checklist): the `Build analyse prompt` step reads `OPENCODE_ANALYSE_ENABLE_DECISIONS`, `OPENCODE_ANALYSE_DECISIONS_{PROVIDER,MODEL,MODE,MIN_PROBABILITY,TIMEOUT}` and the fallbacks `OPENCODE_REVIEW_REPORT_DECISIONS_{PROVIDER,MODEL,TIMEOUT}` (non-secret); both decision provider keys (`OPENCODE_GO_OPENAI_API_KEY` and `OPENCODE_OPENROUTER_API_KEY`) are mapped at analyse job scope, so earlier steps and the opencode model process inherit them too. Only `score-findings-decisions.sh` uses the selected key for a decision HTTP request, passing it to curl through a 0600 header file; `GH_TOKEN` is mapped on the `Build analyse prompt` step for `gh pr diff` / `pr view` / `run download`. That step launches no model. **Since LADR-098** that step reuses the gate's own fix/skip answers from the run artifact when still valid, judges the diff as of the reviewed commit via `review-diff.sh` (and skips the decision step when that diff cannot be fetched), and passes `--rev` only from the `review-diff.sh` branch — an older `recommend-fix-skip.sh` on the PR branch rejects it. Every run uploads `ai-analyse-run-<run_id>` (prompt, FIX/SKIP table, withhold reports, recommendations, test-gate report — a named list, snapshotted outside the checkout before the test gate and redacted to `<REDACTED>` by `redact-secrets.sh` before upload — nothing is uploaded if redaction cannot run; never the raw PR diff or body, never the gate's artifact), and this skill's tests run in the blocking regression job.
